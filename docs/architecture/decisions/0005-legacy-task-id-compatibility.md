# ADR 0005：保留旧 Task ID 的兼容周期

- 状态：Accepted
- 日期：2026-09-03

## 背景

现有脚本、日志、checkpoint 和用户习惯依赖 16 个 `Mjlab-*` Go2 ID。一次性改为机器人优先的新 ID 会让架构迁移与行为变化混在一起，并使历史实验难以复现。

## 决定

Catalog 将新技能 ID 作为领域主键，同时在至少一个正式兼容周期内保留全部旧 `Mjlab-*` ID。新旧 ID 必须解析为等价的环境与训练配置；旧 Python 模块只保留无实现的 alias。删除兼容项必须单独发布弃用通知和迁移表。

## 替代方案

- 立即删除旧 ID：目录最干净，但会破坏现有自动化和历史命令。
- 永久以旧 ID 为主键：短期稳定，却继续把算法名称编码为任务概念。
- 通过字符串规则动态翻译：实现小，但无法枚举、审计或拒绝歧义。

## 后果

用户可以逐步迁移，当前 checkpoint 和验证脚本保持可运行；代价是注册表暂时包含两套名称，并需要等价性测试防止配置分叉。

## 迁移影响

16 个旧 ID 与 8 个新技能 ID 均由 LainLoco entry point 注册。训练和导出 workflow 通过 Experiment binding 解析到旧 registry ID，Catalog 测试持续核对别名、配置工厂和唯一性。
