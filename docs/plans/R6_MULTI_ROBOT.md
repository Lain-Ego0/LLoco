# R6：多机器人证明与发布

状态：`⬜ NOT ACTIVE`。

## 目标

使用一个自研机器人和一个独立来源的成品机器人证明 RoboLab 的 Task、Artifact、Skill、Validation 和 Runtime 契约可复用。

## 进入条件

- R5 simulation deployment、故障注入和 SAFE 验收全部通过；
- 自研机器人已经完成 R2–R5 纵向闭环；
- 当前阶段已在 `plans/README.md` 激活；
- 成品机器人只在本阶段调研后选型，不从历史样板默认继承品牌。

## 本阶段不做

- 不以“两个模型能被加载”替代两个机器人共享完整契约的证明；
- 不复制第一台机器人的 task、runner、FSM 或 Skill 工作流形成第二套产品路径；
- 不在缺少硬件、许可证或安全条件时承诺实机验收；
- 不把特定厂商适配字段提升为所有机器人的公共必填字段。

## 工作项

| ID | 工作项 | 验收 |
|---|---|---|
| R6.1 | 自研机器人完整闭环 | Profile -> train/play/evaluate/export -> Skill -> sim deploy |
| R6.2 | 成品机器人适配 | 不预设品牌，使用相同公共接口 |
| R6.3 | 抽象复用审查 | 不复制完整 task、runner、FSM 或 Skill 工作流 |
| R6.4 | 早期选型迁移报告 | 删除依赖、可复用经验和重新接入条件明确 |
| R6.5 | Upstream sync rehearsal | 冲突、回归和回滚记录完整 |
| R6.6 | End-to-end acceptance | 干净环境重放两类机器人代表流程 |
| R6.7 | 发布收口 | 用户/开发指南、限制、许可证和回滚同步 |

## 退出条件

至少一个自研机器人和一个成品机器人共享同一套公共契约并分别提供可复查证据。
